# 05. 실험 매트릭스 — 사전등록

- 작성일: 2026-09-07
- 원칙: 단계마다 **하나의 질문**에 답하고, 답을 고정한 뒤 다음 단계로 간다. 단계 안에서 돌릴 run과 선택 규칙은 결과를 보기 전에 여기 적힌 대로다.
- 공통: snapshot `2026-08-23`, formation `2015-01-02 ~ 2025-07-31`, 5-fold, `embargo = purge = h`, 유니버스 기본 필터, flow `lag1`, 시드 0(E4 제외).

## 1. 단계 요약

| 단계 | 질문 | run 수 | 예상 시간 | 선행 |
|---|---|---:|---:|---|

## 2. 단계별 상세

### E0 — 기준선 재현 (8 run)

| run | h | 라벨 | 모델 | FS | 전처리 |
|---|---|---|---|---|---|
| E0-1~4 | 5/20/60/120 | `y_rank` | M-A (기존 hgb, `tree` 프로파일) | FS0 | 기존 |
| E0-5~8 | 5/20/60/120 | `y_rank` | M-A (`rank` 프로파일) | FS0 | rank |

- 답할 것: (i) 경계 2025-07-31에서 baseline Rank IC가 기존 게이트 값(h5 0.1155 / h20 0.1436 / h60 0.1753)과 얼마나 다른가 — 다르면 이유는 구간이다. (ii) h120 baseline이 처음 생긴다. (iii) `rank` 전처리가 `tree`와 같은 수준인가 — 같으면 이후 전부 `rank`로 간다.
- isotonic으로 p를 만들어 log-loss·ECE도 기록한다. 이것이 **확률 기준선**이다.
- 선택 규칙: `rank` 프로파일의 Rank IC가 `tree`의 −0.005 안이면 `rank` 채택(전처리 통일). 아니면 `tree`를 유지하고 그 이유를 적는다.

### E1 — 라벨 × 모델 (16 run)

FS0 고정. h마다 4 run.

| 라벨 | 모델 | grid |
|---|---|---|
| L-A `y_up` | M-B HGB-clf | 4개(`max_iter` 400, `l2` 0, `lr`×`leaf`) |
| L-A `y_up` | M-C logit | 3개 |
| L-B `y_top` | M-B | 4개 |
| L-B `y_top` | M-C | 3개 |

- 답할 것: h마다 (라벨, 모델) 하나.
- **선택 규칙**: 같은 라벨 안에서 valid log-loss가 낮은 모델을 고른다. 라벨 사이는 log-loss를 직접 비교할 수 없으므로(양성 비율이 다르다) **경제성 주 지표**(h5·20·60은 top-k 비용 반영 수익, h120은 Rank IC)로 고른다. 동률(fold 표준편차 안)이면 L-A.
- 예상: M-B가 M-C를 이긴다. 이기지 못하는 h가 있으면 그 h는 피쳐 정보가 선형으로 충분하다는 뜻이고 M-C를 채택한다.
- 기록: E0의 M-A(확률 기준선) 대비 log-loss·ECE 개선.

### E2 — 피쳐 집합 (12 run)

E1의 (라벨, 모델)을 h마다 고정. 16-grid.

| run | FS | 답할 것 |
|---|---|---|
| E2-a | FS1 | 검증 통과 피쳐 16개 추가가 개선하나 |
| E2-b | FS1h | horizon별 부분집합이 FS1보다 나은가 |
| E2-c | FS2 | 매크로 베타 4 + 국면 4 + interaction 4가 개선하나 |

- 비교 사슬: FS0(E1) → FS1 → {FS1h} → FS2. FS2는 FS1과 FS1h 중 **E2-a/b에서 나은 쪽** 위에 얹는다.
- 선택 규칙: `03` §3.3의 개선 판정. 개선이면 채택, 무개선이면 이전 집합 유지. **부분 채택(FS2의 12개 중 일부만) 하지 않는다** — 쌍별 ablation은 E4d다.
- T2 게이트가 h60 비용 반영 spread 0.0204→0.0283을 보였으므로 FS1은 h60에서 개선이 기대된다. h5에서는 T1이 비용 반영에서 실패했으므로 FS1 채택은 의심스럽다.

### E3 — 시점 규칙 (4~8 run)

E2까지 채택된 config를 h마다 고정.

| run | 변형 | 답할 것 |
|---|---|---|
| E3-a (4) | flow 당일 값(`native_t`) | `lag1` 대비 얼마나 좋아 보이나. **좋아 보이는 만큼이 미검증 위험이다** |
| E3-b (4, 조건부) | FS0의 `fin_pit` 10 → strict vintage 재작성(병행 F-9) | PIT 규칙 통일이 결과를 바꾸나 |

- 선택 규칙: E3는 **채택을 바꾸지 않는다.** 결과는 기록만 한다. `native_t`가 크게 좋으면 "당일 집계 사용 가능 여부 검증"이 다음 과제가 된다(수집 스트림). E3-b가 다르면 FS0'를 이후 기준으로 삼는다.

### E4 — 안정성 (12~16 run)

E2 채택 config, h마다.

| run | 변형 | 답할 것 |
|---|---|---|
| E4a (4×2) | 시드 1, 2 추가 | 시드 표준편차. 이후 모든 개선폭의 잣대 |
| E4b (4) | `monotonic_cst`(기대 부호) | 부호 제약이 성능·보정을 해치나 |
| E4c (선택, 4) | 반대 부호 안정 3 family(`px_turnover_shock`, `flow_foreign/inst_netbuy_to_volume_20d_lag1`) 부호 뒤집어 추가 | D등급에 묻힌 정보가 모델에서 사나 |
| E4d (선택, 4×4) | interaction 4개 하나씩 제거 | 각 interaction의 증분 |
| E4e (선택, 4) | `*_isna` 제거 | 결측 패턴이 시대를 학습하고 있나 |

- 선택 규칙: E4b·E4c·E4e가 주 지표 둘 모두에서 채택 config를 이기고 시드 표준편차를 넘으면 그것으로 **교체**한다. 그 외는 기록.
- 선택(optional) run은 예산이 허락할 때만 돈다. 돌리지 않으면 "미실행"으로 적는다.

### E5 — FS3 (병행 스트림, **입력 확정 2026-09-09**)

- 입력: `02` §1.5의 **11 컬럼**(관계 4 + 재무위험·생애주기·전이 7). 출처는 병행 스트림 F-HS-1 —
  config `3ca949e6…`, snapshot `2026-09-08`, 기록 `20260907_additional_feature/results/f_hs1_run_20260909.md`.
  등급은 관계 4개가 A, `fin_*` 7개가 B 상한(`revision_ratio` 0.1015)이다.
- run: 4 h × 시드 3(0·1·2) = **12**. 비교 상대는 E4a가 이미 만든 채택 config의 같은 시드 3개다.
- 방법: E2와 같은 비교(채택 config → + FS3). 채택 config가 FS1h면 FS3도 `02` §1.5 표의 검정 horizon
  밖 h에서는 뺀다.
- 선행: 08-23 snapshot에서 마트 4개 재빌드(`02` §1.5 마지막 항목). FS0~FS2 컬럼은 바뀌지 않는다.
- 선택 규칙: 주 지표 둘 **모두**에서 채택 config를 이기고 개선폭이 E4a 시드 표준편차를 넘으면 FS3를
  채택한다. 그 외는 기록만 한다.
- 부호: `02` §1.5 표의 기대 부호를 E4b식 단조 제약에 쓸 수 있다. 그 표는 F-HS-1이 첫 run 뒤 고정한
  값이고 이 문서에서 다시 고르지 않는다.
- 시점: FS3가 준비됐으므로 남은 선행은 E0~E4다. 결과 문서(M-8)는 E5 없이 먼저 닫는다(§4의 한계 8번).
- 넘어오지 않은 것: event cohort 2 family(`fin_dividend_initiation`, `fin_negative_equity_exit`)는
  `fin_risk_event` 마트가 없어 F-HS-1에서 막혔고, F-3 업종 관계·F-5 파생 family는 F-HS-2 뒤다. 그것들이
  오면 E5를 다시 돌리지 않고 **별 단계**로 적는다.

## 5. 결과를 보고 하지 않는 것

- 주 지표 교체, grid 확장, 임계 τ·k 변경, fold 수 변경, `period_end` 변경.
- FS의 부분 채택(개별 컬럼 골라내기). 하려면 E4d 같은 ablation을 사전에 적는다.
- 라벨 정의 수정(예: `y_up`을 `raw > 1%`로).
- holdout 구간의 어떤 값도 읽지 않는다. 예측 파일도 만들지 않는다.
- E5 결과를 보고 E0~E4의 채택을 되돌리지 않는다. FS3는 "추가"만 한다.
